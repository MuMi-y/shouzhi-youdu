# 完全虚构的参赛开发场景

不含用户个人财务资料。`src.bank_insights.fixture.create_demo(new_bank_path,clock=...)`基于既有V1虚构期初和三月收支，在**全新银行数据库**新增六笔明确虚构扣费；传入已存在文件时拒绝，不能重置原演示库。

初始化时相对日期：云存储3000分分别在87、56、25天前；视频2000、2000、2500分分别在92、61、30天前。原V1合计600000分减去15500分，合计584500分（CNY5845.00）；总17条U1流水，A484500分/B100000分。X是隔离验证用U2账户，不加入报告。

云存储描述与已有M1虚构授权同名仅供展示人工核查；算法不会因同名就假定正式订阅或查代扣。V1已有固定还款、未到账项目收入、购机安排保持各自未来日期及来源。这是一个新的虚构场景，不能声称原库余额已变成5845。

`replay_cases.json`是运行评估前冻结的14条有限规则真值：三次证据/不足、未来隐藏、月/周、涨价/降价、无序、内部转账/退款排除、未确认静默、忽略/拒绝、更正、未观察到预计扣费。每条按交易日期顺序回放前缀，最后执行反馈和重复检查。它只支持规则验收，不代表真实用户体验。资金缺口、退款缓解、收入延迟的财务预测沿用bank_v1独立用例，不在这里假造第二套金额规则。
